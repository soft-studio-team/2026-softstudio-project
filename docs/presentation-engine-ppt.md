# 가격 추출 엔진 — PPT 구성 + 멘트

A가 마이페이지까지 말한 뒤 이어받는다. 약 4분.
슬라이드 4장. **대본은 슬라이드에 올리지 않는다.** 화면은 크게, 글은 불렛 3개.

템플릿은 `내 친구 페이지` / `살까말까 페이지`와 같게:
왼쪽 위 빨·노·초 점 + 굵은 제목, 연회색 바깥 / 흰 카드, 폰 캡처, 갈색 낙서선.

---

## 찍어야 하는 화면

| 쓸 곳 | 장면 |
|---|---|
| 1장 왼쪽 | 무신사(또는 에이블리) 상품 → 공유 시트에서 wishkit |
| 1장 오른쪽 | 공유 담기. 이름·정가·판매가·사진이 채워진 카드 |
| 2장 ① | 같은 공유 시트 |
| 2장 ② | 공유 담기. URL만 들어온 직후 |
| 2장 ③ | `상품 페이지를 읽는 중...` |
| 2장 ④ | 채워진 카드 (1장 오른쪽과 같아도 됨) |
| 2장 ⑤ | 위시 홈. 그 카드가 폴더에 들어간 화면 |
| 3장 왼쪽 | 담기 화면 가격 칸. 라벨이 `기본 판매가 (쿠폰·옵션 제외)` |
| 3장 오른쪽 | 가격만 비고 `가격을 직접 입력해 주세요` 인 담기 화면 |
| 4장 왼쪽 | 위시 홈. 무신사·29CM·에이블리 카드가 한 화면 |
| 4장 오른쪽 | 같은 홈이거나, 지원 몰 로고를 텍스트로 둬도 됨 |

영상은 소리 없이 8~20초. 1장 공유→채움이 제일 중요하다.

---

## 1장. 가격 추출 엔진 — 50초

**레이아웃:** `내 친구 페이지`와 같음.
왼쪽 폰 + 가운데 설명 + 오른쪽 폰.

```
● ● ●   가격 추출 엔진

 [공유 시트]          자동 채움           [공유 담기]
  쇼핑몰 → wishkit                      채워진 위시 카드
                    · 쇼핑 앱에서 공유하면
                      wishkit이 링크를 받음
                    · 이름 · 정가 · 판매가 · 이미지를
                      위시 카드로 남김
                    · 제가 맡은 일은 이 자동 채움
```

**슬라이드에 올릴 글**
- 소제목: 자동 채움
- 쇼핑 앱에서 공유하면 wishkit이 링크를 받음
- 이름 · 정가 · 판매가 · 이미지를 위시 카드로 남김
- 제가 맡은 일은 이 자동 채움

**멘트**

방금 보신 공유로 카드가 채워지는 부분, 그게 가격 추출 엔진입니다.
쇼핑 앱에서 공유를 누르면 wishkit이 링크를 받습니다.
그리고 이름, 정가, 판매가, 이미지를 위시 카드로 남깁니다.
제가 맡은 일은 그 자동 채움입니다.

엔진이 카드에 넣는 것은 이겁니다.
상품 이름, 정가, 판매가, 대표 이미지, 상품 URL, 어느 쇼핑몰인지.
고민하는 이유 메모는 엔진이 가져오지 않습니다.
그건 저장한 뒤에 사용자가 적습니다.

## 2장. 단말에서 페이지를 읽습니다 — 1분 10초

**레이아웃:** `살까말까 페이지`와 같음.
위쪽에 폰 5개 + 화살표, 아래 불렛 3개.

```
● ● ●   단말에서 페이지를 읽습니다

 [공유] → [URL] → [WebView] → [그려진 뒤] → [카드]
  시트     담기     읽는 중      채움         위시 홈

 · 서버에서 긁거나 파이썬 API를 부르지 않음
 · 공유 담기는 전부 이 한 길
 · 사용자가 보던 그 상품 페이지를 단말에서 그대로 읽음
```

폰 아래 작은 캡션 (선택):
1. 공유
2. URL
3. 단말 WebView
4. 그려진 뒤 읽기
5. 위시 카드

**슬라이드에 올릴 글**
- 서버에서 긁거나 파이썬 API를 부르지 않음
- 공유 담기는 전부 이 한 길
- 사용자가 보던 그 상품 페이지를 단말에서 그대로 읽음

**멘트**

예전에는 서버에서 페이지를 긁거나, 파이썬 파싱 API를 앱이 부르는 방식도 있었습니다.
지금은 그렇게 하지 않습니다.

흐름은 한 줄입니다.
공유로 URL이 들어오면, 사용자 휴대폰 안의 WebView가 그 상품 페이지를 엽니다.
페이지가 그려진 뒤에, 그 화면에서 정보를 읽습니다.
읽은 값을 담기 화면의 카드로 돌려줍니다.

공유 담기는 전부 이 한 길로 통일했습니다.
서버 파싱 주소나 파이썬 폴백은 앱에서 빼 두었습니다.

서버 IP로는 막히는 몰이 많습니다.
가격이 자바스크립트로 늦게 붙는 페이지도 많습니다.
그래서 사용자가 보던 그 상품 페이지를, 단말에서 그대로 읽는 편이 맞았습니다.

## 3장. 조건 없는 가격만 — 1분

**레이아웃:** `내 친구 페이지`와 같음.
왼쪽 = 채워진 가격 칸, 오른쪽 = 가격이 비어 직접 입력.

```
● ● ●   조건 없는 가격만

 [기본 판매가]         가격 기준          [직접 입력]
  쿠폰·옵션 제외                         가격 칸이 비어 있음
                    · 쿠폰가 · 회원가 · 첫구매가는
                      정답으로 쓰지 않음
                    · 조건 없는 판매가 · 리스트가를 우선
                    · 못 읽으면 그 칸만 비우고
                      가격은 직접 입력
```

**슬라이드에 올릴 글**
- 소제목: 가격 기준
- 쿠폰가 · 회원가 · 첫구매가는 정답으로 쓰지 않음
- 조건 없는 판매가 · 리스트가를 우선
- 못 읽으면 그 칸만 비우고, 가격은 직접 입력

**멘트**

가격은 아무 숫자나 고르지 않습니다.
화면에 쿠폰가, 회원가, 첫구매가가 같이 있어도, 그 숫자는 정답으로 쓰지 않습니다.
조건 없는 판매가, 리스트가를 우선합니다.
앞에서 말한 것처럼, 쿠폰 · 카드 할인 · 옵션 추가금은 빼는 것과 같은 기준입니다.

몰마다 가격이 어디에 붙어 있는지가 다릅니다.
확인한 몰은 전용 규칙을 두고, 그 규칙으로 못 읽으면 다른 숫자의 가격으로 우회하지 않습니다.

정확히 못 읽으면 그 칸만 비웁니다.
이름과 URL은 남기고, 가격은 직접 입력할 수 있습니다.
자동이 전부여야 하는 구조가 아닙니다.

## 4장. 되는 몰, 안 되는 몰 — 1분

**레이아웃:** `내 친구 페이지`와 같음.
왼쪽 폰(여러 몰 카드) + 가운데 설명 + 오른쪽은 폰 대신 칩.

```
● ● ●   되는 몰, 안 되는 몰

 [위시 홈]            지원 범위           에이블리  무신사  지그재그
  여러 몰 카드                            퀸잇  KREAM  29CM
                    · Tab S7에서 이름·가격·이미지   4910  W컨셉  SSF샵
                      를 맞춰 약 50곳               올리브영
                    · 회귀는 패션 인기몰부터
                    · 쿠팡 · 네이버는 지원 범위 밖
```

오른쪽 칩은 캡처 대신 텍스트로 둬도 된다.
아래 갈색 낙서선 옆에 작은 한 줄 (선택):
`로드가 끝나기 전에 읽지 않음 · 같은 사이트의 다른 주소는 같은 몰`

**슬라이드에 올릴 글**
- 소제목: 지원 범위
- Tab S7에서 이름 · 가격 · 이미지를 맞춰 약 50곳
- 회귀는 패션 인기몰부터
- 쿠팡 · 네이버는 지원 범위 밖

오른쪽 칩: 에이블리, 무신사, 지그재그, 퀸잇, KREAM, 29CM, 4910, W컨셉, SSF샵, 올리브영

**멘트**

검증은 Galaxy Tab S7에서 했습니다.
실제 상품 페이지와 엔진 결과를 맞추는 live field compare입니다.
이름, 가격, 이미지까지 같으면 MATCH로 봤습니다.
지원으로 말하는 몰은 약 50곳입니다.
이 코드는 풀 리퀘스트 28로 main에 들어가 있습니다.

회귀할 때는 50곳을 매번 다 보기보다, 패션 인기몰을 먼저 봅니다.
에이블리, 무신사, 지그재그, 퀸잇, KREAM, 29CM, 4910, W컨셉, SSF샵, 올리브영입니다.

쿠팡이나 네이버처럼 접근이 막히거나, 일부러 기권한 몰은 지원 목록에 넣지 않습니다.
엔진이 전부 실패한 게 아니라, 지원 범위 밖의 문제입니다.

짧게 두 가지만 더 말씀드리겠습니다.

에이블리처럼 한 페이지에서 화면이 바뀌거나, m이랑 mobile처럼 주소가 갈리는 몰이 있습니다.
로드가 끝나기 전에 읽으면 값이 비었습니다.
같은 사이트 안에서 맞춘 뒤, 그려질 때까지 기다리고 읽도록 맞춰 갔습니다.

또 공유로 오는 글에는 짧은 링크나, 상품 주소가 문장 속에 섞여 있는 경우가 있습니다.
그중 URL을 찾아 같은 WebView로 엽니다.
완전히 다른 사이트로 새면 그 결과는 쓰지 않습니다.

여기까지가 카드를 어떻게 채우는지입니다.
